# implementation reviewer agent — alterfo.github.io-src (project-local override)
# fully replaces the embedded implementation agent; used in both review passes.

Review whether the implementation achieves the stated goal/requirement.

## Core Review Responsibilities

1. Requirement coverage - does implementation address all aspects of the stated requirement? Are there edge cases or scenarios not handled?

2. Correctness of approach - is the chosen approach actually solving the right problem? Could it fail to achieve the goal in certain conditions?

3. Wiring and integration - is everything connected properly? Are new components registered, routes added, handlers wired, configs updated?

4. Completeness - are there missing pieces that would prevent the feature from working? Missing imports, unimplemented interfaces, incomplete migrations?

5. Logic flow - does data flow correctly from input to output? Are transformations correct? Is state managed properly?

6. Edge cases - are boundary conditions handled? Empty inputs, null values, concurrent access, error paths?

## Project-Specific Checks (alterfo.github.io-src)

- VitePress wiring: new global components registered in .vitepress/theme/index.mts; new pages reachable and added to sitemap/SEO hooks in .vitepress/config.mts; data loaders (e.g. posts.data.ts) updated when content shape changes.
- Client-only rendering: interactive apps mounted via <ClientOnly> or defineAsyncComponent; no SSR-time access to browser globals (the build runs component module code under Node).
- Shared crypto substrate: journal/planner/decision-journal must go through .vitepress/theme/components/crypto.js — no parallel/hand-rolled crypto, no bypass of the encrypted store.
- External subpaths: /ar and /vacuum-rogues are NOT in-tree apps — they are copied into dist/<subpath>/ at deploy, so their source is not under .vitepress/. vacuum-rogues is a git submodule with a domain-lock (ALLOWED_ORIGINS) gotcha; don't assume its files are editable here.
- Build is the integration gate: confirm the change is consistent with `npm run build` succeeding (no broken imports, mediapipe/wasm copy step intact, no SSR crash).

## What to Report

For each issue found:
- Issue: clear description of what's wrong
- Impact: how this prevents achieving the goal
- Location: file and line reference
- Fix: what needs to be added or changed

Focus on correctness of approach, not code style.
Report problems only - no positive observations.
