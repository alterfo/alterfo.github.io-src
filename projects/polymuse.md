# polymuse

Бриф на YAML — режим, темп, циклы, секции, настроение, целевая громкость — превращается в
партитуру. Дальше её читает агент-критик, потом человек. Только после этого — рендер в MIDI и WAV.

```
brief.yaml → Score → critic → (human) → MIDI + WAV
```

## Зачем

Полиметрия руками пишется медленно: пока сведёшь три цикла в один такт, потеряешь идею. Мне
хотелось задавать намерение словами и получать материал, который можно править, а не готовый
трек «как у всех».

Критик нужен, чтобы не тащить в рендер явную ерунду. Он разбирает партитуру по тем же правилам,
что и я: где голоса сталкиваются, где пропадает дыхание, где секция не работает.

## Как устроено

- Партитура — данные, а не аудио. Её можно показать, сравнить, отредактировать.
- Рендер идёт через инструмент Lumen: `lumen-kit --score` собирает звук из той же партитуры.
- Оркестрация — несколько агентов с разными ролями: композитор, критик, аранжировщик.

## Состояние

Работает, репозиторий закрытый. Слушать результат — в разделе [музыки](/music).

- Больше форм: не только циклы, но и свободные разделы.
