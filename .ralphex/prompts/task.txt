PROJECT CONTEXT (alterfo.github.io-src):
VitePress static site with fully client-side apps (idef0, journal, piano, openpose, planner, decision-journal, music) plus two external apps served as subpaths (/ar, /vacuum-rogues). Read the repo-root CLAUDE.md AND the CLAUDE.md inside the module subfolder you are touching before implementing. This repo is GitNexus-indexed: prefer mcp__gitnexus__* over grep. Before editing a symbol run impact({target, direction:"upstream"}); explore with query/context; rename symbols with the rename tool, not find-replace.

PROJECT RULES — hard invariants, never violate them:
- Package manager is npm, NOT yarn (yarn is broken in this repo). Use `npm run dev` / `npm run build`. Never re-add yarn.lock, .yarnrc.yml, or a packageManager field.
- No CDN at runtime. Vendor third-party libraries locally or use a native browser API. Never load a library or asset from a CDN URL at runtime.
- No plaintext projection of E2EE data. journal, planner, and decision-journal are end-to-end encrypted (WebCrypto AES-GCM via .vitepress/theme/components/crypto.js). Never add a filesystem bridge, cache, log, or export that writes decrypted user data to disk — even for agent/debug convenience. Privacy over feature.
- UI must derive from the "Spiral" design system (.vitepress/theme/components/spectrum.js palette; see .vitepress/CLAUDE.md). Do NOT introduce generic "Claude Code"-style chrome (e.g. a "← Главная" pill).
- Russian-language typography: a non-breaking space (U+00A0) goes before an em dash «—». In markdown this is handled by a rule in .vitepress/config.mts; in hand-written UI strings do it by hand. NBSP is fragile in editors/shell — verify with charCodeAt when unsure.
- Articles/blog: tool docs use no first person and no personal stories — facts only. Do NOT author or modify blog post content unless the plan explicitly says so; blog content needs the author's review.
