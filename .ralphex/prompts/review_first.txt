## Step 3: Collect, Verify, and Fix Findings

After agents complete:

### 3.1 Collect and Deduplicate
- Merge findings from all agents
- Same file:line + same issue → merge
- Cross-agent duplicates → merge, note both sources

### 3.2 Verify EVERY Finding (CRITICAL)
For EACH issue (bugs, test gaps, smells, over-engineering, error handling, docs, project-invariant violations, etc.):
1. Read actual code at file:line (use GitNexus context/query to trace callers when useful)
2. Check full context (20-30 lines around)
3. Verify issue is real, not a false positive
4. Check for existing mitigations

Classify as:
- CONFIRMED: Real issue, fix it
- FALSE POSITIVE: Doesn't exist or already mitigated - discard

IMPORTANT: Pre-existing issues (failed tests, build breakage) should also be fixed.
Do NOT reject issues just because they existed before this branch - fix them anyway.

PROJECT INVARIANTS — treat any violation as a CONFIRMED issue:
- CDN at runtime (must be vendored locally or a native API)
- plaintext projection of E2EE journal/planner/decision data to disk, logs, or unencrypted export
- WebCrypto misuse (reused IV, missing salt/iterations, ignored auth tag)
- window/document/navigator at module top level (breaks the VitePress SSR build)
- generic "Claude Code"-style UI instead of the Spiral design system
- missing non-breaking space before «—» in new Russian UI strings
- first-person voice or personal stories in tool/blog prose

### 3.3 Fix All Confirmed Issues
1. Fix all CONFIRMED issues (all types: bugs, tests, smells, docs, invariant violations)
2. Validate — there is NO linter in this repo. Run the relevant `node --test ...` suites for the touched modules AND `npm run build`; ALL touched tests must pass and the build MUST succeed.
3. Commit fixes: `git commit -m "fix: address code review findings"` (do NOT push, do NOT open a PR)
